Un agente
personale vivo.

OpenMate vive sul tuo dispositivo come un daemon: si sveglia da solo a intervalli (heartbeat), coltiva una memoria di lungo periodo, usa la shell e i tool per agire — e ti chiede il permesso prima delle azioni rischiose. Qui trovi per filo e per segno cosa fa e come.

01

Cos'è, in una riga

Non è un chatbot che risponde quando lo interroghi. È un'entità autonoma e persistente con continuità, iniziativa e memoria — pensata per diventare, col tempo, una presenza familiare (esperienza simil-tamagotchi).

Local-first

Dati e memoria restano sul tuo dispositivo. La rete serve solo al modello LLM.

Memoria trasparente

La conoscenza durevole è markdown leggibile e versionabile, non un blob opaco.

Agente attivo

Decide lui cosa ricordare, cosa fare e quando cercare in memoria. Non subisce, agisce.

Sicurezza by-design

Autonomia + shell + tool = potere. Ogni azione ad alto impatto passa da permessi e audit.

04

La memoria

Il differenziatore del progetto. Non uno storico chat, ma un cervello a livelli. Le idee "wiki", "filesystem long-term" e "short-term" non competono: sono strati.

core memory · persona.md / user-profile.md

Sempre in contesto

Chi è l'agente e chi sei tu. Iniettata ad ogni ciclo, mai indicizzata: è l'identità che dà continuità.

episodic · tabella SQLite + episodic_fts

Cosa è successo

Log append-only di eventi e azioni con timestamp. Indicizzato in FTS5 per il recall.

semantic · memory/notes/*.md (gray-matter)

Conoscenza durevole

La LLM Wiki: note markdown con frontmatter e link [[…]]. File leggibili, versionabili con Git, indicizzati in wiki_fts.

retrieval · memory.search()

Ricerca keyword (bm25)

FTS5 su episodic + semantic. Nell'MVP è keyword-only; il vettoriale e il consolidamento arrivano in Fase 3.

# memory/notes/errore-migrazione.md
---
name: errore-migrazione
description: Ultimo errore trovato nei log
type: reference
---
Errore ECONNREFUSED durante la migrazione.
Collegato a [[progetto-x]].
// recall agentico: l'agente decide QUANDO cercare
memory.search("errore migrazione", { scope: "all" })
// → [{ ref:{kind:"semantic",name:"errore-migrazione"},
//     score, snippet, source:"semantic" }, …]

Editi un .md a mano? All'avvio la riconciliazione content-hash re-indicizza solo ciò che è cambiato. Il file è la fonte di verità; l'indice è derivato.

05

Tool & sicurezza

I tool sono l'unico modo in cui l'agente tocca il mondo. Ogni chiamata passa da un gate: permesso statico + un controllo per-parametro, poi approvazione e audit.

safe

Nessun effetto rilevante. Esegue senza chiedere. Es. memory.search, computer.screenshot (Fase 2).

guarded

Effetti limitati/reversibili. Esegue, ma un hook needsApproval può alzare la mano. Es. shell.run, file.write.

dangerous

Effetti potenzialmente irreversibili → approvazione obbligatoria. Es. input GUI, comandi di sistema.

// shell.run: 'guarded', ma decide per comando
needsApproval(cmd, policy) {
  if (policy.shell.deny.match(cmd)) return true;
  if (policy.shell.allow.length === 0) return true;
  return !policy.shell.allow.match(cmd);
}
// "echo hi"  → allowlisted → esegue subito
// "rm -rf …" → non allowlisted → chiede

Il gate è centralizzato: valida l'input (zod), decide se serve l'approvazione, esegue, e scrive sempre nell'audit (auto / approved / denied).

// audit log append-only (SQLite)
{ ts, tool: "shell.run",
  input: { command: "grep -i error app.log" },
  decision: "approved",
  outcome: "ok" }
